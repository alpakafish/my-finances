# Мои финансы — skill для работы с репозиторием

Локальный веб-сервис учёта личных расходов и доходов. Полное описание проекта, скриншоты
и список функций — в [README.md](../../../README.md).

## Структура репозитория

```
server.js              — точка входа Express-приложения
db.js                   — SQLite (node:sqlite, встроен в Node): схема, миграции, сиды категорий по умолчанию
routes/
  transactions.js       — CRUD операций (GET/POST/PUT/DELETE /api/transactions)
  categories.js         — CRUD категорий, включая rollup_id (см. ниже) и защиту удаления
  summary.js            — помесячная сводка и overview для графиков дашборда
  goals.js              — цели накопления: создание, взнос, прогресс, дедлайн
  import.js             — импорт операций из Excel (multer + exceljs)
  export.js             — экспорт операций и сводки в Excel (exceljs)
public/
  index.html            — вся разметка (4 вкладки: Дашборд/Операции/Категории/Цели)
  app.js                — вся клиентская логика (без сборки, без фреймворка)
  styles.css            — стили в духе «плоского» минимализма (см. палитру в начале файла)
  vendor/chart.umd.js   — Chart.js, подключён локально (офлайн-режим)
data/smeta.db           — SQLite-файл с данными пользователя (в .gitignore, не публикуется)
scripts/seed-demo-data.js — генерирует безопасные демо-данные поверх ПУСТОЙ базы (для скриншотов)
```

Технологии: Node.js, Express, `node:sqlite` (встроенный в Node драйвер, не npm-пакет — см. ниже,
почему это важно), ванильный HTML/CSS/JS, Chart.js, ExcelJS. Никакой сборки (webpack/vite) нет —
`public/` отдаётся как статика напрямую.

**Почему `node:sqlite`, а не `better-sqlite3`**: `better-sqlite3` — нативный модуль, при `npm install`
на машине без прекомпилированного бинарника под конкретную версию Node пытается собраться из
исходников через node-gyp, для чего нужны настроенные C++ build tools (Visual Studio Build Tools
на Windows, Xcode Command Line Tools на macOS) — на компьютере обычного пользователя их обычно
нет, и установка падает без понятной ошибки. `node:sqlite` — часть самого Node.js (с 22 LTS),
компилировать нечего, `npm install` не трогает нативный тулчейн вообще. `db.js` добавляет поверх
него `.pragma()` и `.transaction()` (последний — через SAVEPOINT, чтобы поддерживать вложенные
вызовы, как в `routes/import.js`), чтобы весь остальной код мог использовать привычный API
better-sqlite3 и не меняться при будущих правках.

## Ключевая концепция: rollup-категории (цели накопления)

Категория может иметь `rollup_id`, указывающий на другую категорию. Операции в такой категории
видны как есть в списке операций, но при подсчёте на Дашборде и в Excel-сводке суммируются в
категорию-цель (обычно «Сбережения»). Это то, как цели накопления не дробят общую картину
расходов. Логика свёртки — в `routes/summary.js` (`categoryBreakdown`) и `routes/export.js`.
При добавлении новых мест, где считаются суммы по категориям, не забывай учитывать `rollup_id`.

## Как запустить локально

```bash
npm install
npm start
```

Откроется на http://localhost:3000. Либо двойной клик по `start.command` (Mac) / `start.bat`
(Windows) — сам поднимет сервер и откроет браузер.

При первом запуске `db.js` создаёт `data/smeta.db` и сеет дефолтные категории — база пустая,
это нормально.

## Как вносить изменения

- Бэкенд — обычный Express, роуты в `routes/*.js`, вся работа с БД через `db.js` (node:sqlite,
  синхронный API в духе better-sqlite3, без ORM).
- Фронтенд — без сборки: правишь `public/app.js`/`public/index.html`/`public/styles.css` и
  обновляешь страницу в браузере, npm-скрипт пересобирать не нужно.
- Новую вкладку в интерфейсе — по образцу существующих: секция в `index.html` внутри
  `.tab-panel`, кнопка в `.tabs`, обработчик переключения в `app.js` (`document.querySelectorAll('.tab-btn')`).
- Палитра и переиспользуемые компоненты (кнопки, тултипы, карточки) — в начале `public/styles.css`,
  ориентируйся на существующие классы (`.btn`, `.card`, `.tooltip-wrap`, `.insight`), не изобретай новые
  стили без необходимости.

## Как проверять ошибки

Готовых автотестов в проекте нет (это MVP). Проверка — вручную:

1. Запусти сервер (`npm start`) и открой http://localhost:3000.
2. Пройди по вкладкам: добавь операцию, отредактируй/удали категорию, создай цель и внеси взнос,
   сделай экспорт/импорт Excel.
3. Смотри консоль браузера (DevTools → Console) и терминал, где запущен `node server.js`, —
   ошибки печатаются туда.
4. Если правишь `db.js` (схему), удали `data/smeta.db` и перезапусти сервер, чтобы проверить
   миграцию/сиды на чистой базе — но **не делай так с базой, где есть настоящие данные
   пользователя**, сначала скопируй файл для бэкапа.

## Как готовить проект к публикации

- Данные пользователя (`data/*.db*`) уже в `.gitignore` — не коммить их и не снимай скриншоты
  с реальными финансовыми данными для публичного репозитория.
- Для скриншотов используй `node scripts/seed-demo-data.js` — он ОЧИЩАЕТ `data/smeta.db` и
  наполняет его выдуманными данными. Перед запуском на базе с реальными данными обязательно
  сделай бэкап файла `data/smeta.db` (`cp data/smeta.db куда-нибудь-вне-репозитория`) и
  восстанови его после того как отснимешь скриншоты.
- README уже оформлен по структуре (Проблема/Пользователь/Основная функция/Формат результата/
  Скриншоты/MVP/Технологии) — при значимых изменениях функционала обновляй разделы «Минимальный
  функционал» и, если нужно, переснимай скриншоты.
- Публикация: `git add -A && git commit -m "..." && git push`. Репозиторий уже привязан к GitHub
  (`git remote -v` покажет `origin`), новый `gh repo create` не нужен.
